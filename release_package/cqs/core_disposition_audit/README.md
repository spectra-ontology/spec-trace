# Core disposition audit

This diagnostic overlay accounts for all 560 original questions: **494 contract-verified, 14 requiring clarification, and 52 with evidence verification incomplete**. The fourteen comprise five unresolved operational metrics, five missing required inputs, one missing result extent, and three conflicting TR study descriptions. The existing current-core index remains 494 admitted and 66 nonadmitted. Reclassifying those 66 adds no solved question, model score, human review, or expert validation.

The classification uses the pinned current **question-first semantic review criteria**: derive the requested meaning from the original English and preserved source context before checking a query. This scope matters. The original queries already choose executable metrics, and the legacy query-derived contracts record their ordering and cutoffs. **If those queries are adopted as the normative task specification, the corresponding operational choice is fixed.** These diagnostics then show sensitivity to a different chosen metric, rather than multiple correct results for that fixed query. The alternative metrics here are illustrative probes, not replacement gold answers.

Run the complete portable check with Python 3 and its standard library:

```sh
python verify_package.py
```

The check loads the bundled compressed conditional graph witnesses into an in-memory SQLite database and compares their aggregates with separate Python set recounts. It also checks a conditional recent-meeting witness with calendar order and counts held fixed, then rebuilds the disjoint 560-item overlay. Meeting counts in that additional witness are retained derived observations: the portable extent check does not recount archived TDoc edges. It requires no private database, API, model credit, or network connection. To regenerate the overlay elsewhere:

```sh
python build_partition.py --candidates metric_classification_candidates.json --candidates missing_input_classification_candidates.json --candidates extent_classification_candidates.json --candidates conflicting_entity_description_candidates.json --output-dir audit-output
```

The trend questions explicitly concern **Resolutions**. Their diagnostic ambiguity is normalization and its denominator; changing their unit to TDocs is not used as evidence. Company names are matched literally, without inferred corporate aliases. Recorded references and submitter metadata do not establish ownership, causal influence, actual approval, or incorporation into a standard. The area counts do not measure implementation difficulty.

`RAN4_P1_CQ5-2` asks for the most recent meetings and their TDoc counts without specifying how many meetings or a time window. Its original query chooses `LIMIT 5`; the old fixture records a minimum of five rows. These implementation choices are preserved as counterevidence. The historical design's explicit default-limit matrix covers CQ1–4, without a CQ5-2 binding. Under the question-first policy, an extent must be stated before complete-list scoring. On the same 58 meeting records and source-supported chronology, conditional lists of five and ten meetings have different memberships. The comparison changes only the extent, with meeting identities, temporal order and counts fixed; neither list is replacement gold. Both separate seven-unit AI judgments, original design excerpts, the opposing query-normative interpretation and the actual private SQL count receipt are bundled. The calendar ledger was previously source-audited; this check does not claim a fresh reading of every original report.

To repeat the additional count check against a restored immutable database, run `python reproduce_extent.py --database PATH/RAN4.sqlite`. Without that optional database, the script verifies only the bundled conditional extent and chronology. The old query's canonical-name tie ordering also places a numbered meeting before its later bis meeting; that separate defect is not used to establish the missing extent.

Three additional cases have source-authenticated conflicting study descriptions: `RAN1_P5_CQ5-1` names TR 38.859 as Ambient IoT although its archived title/Scope identifies NR positioning; `RAN1_P5_CQ5-2` labels TR 38.802 as RedCap although it identifies New Radio physical layer aspects; `RAN4_P5_CQ4-3` labels TR 38.860 as RedCap RF although it identifies the Extended 600 MHz NR band study. Their `conflicting_entity_description` classification is conditional on requiring consistent named descriptions or an explicit truthful false-premise response policy. If numeric identifiers and original queries are normative, an answer can explicitly correct the description and retain the fixed identifier. No different TR is substituted. The portable evidence in `sources/conflicting_TR_description_evidence/` contains exact original English/query hashes, 13 source paragraph XML witnesses, archive/member/full-XML pins, and separate seven-unit checks by two AI reviewers. Its default check verifies the bundled evidence and rejects wrong question hashes, source identities and missing title witnesses; optional `--source-root` additionally reopens the pinned originals. Different official study titles do not prove absence of every body mention of another technology. Bibliography completeness, incoming reference coverage and actual study-to-spec outcome evidence remain separately pending, and none of these three becomes an admitted answer. The broader Agenda 7.1/MIMO case remains evidence-pending because a maintenance heading alone does not exclude a MIMO-topic intersection.

`sources/five_original_question_query_and_legacy_contract_records.json` preserves the exact five English questions, original queries, and countervailing legacy contracts. `sources/preserved_source_context_excerpts.json` includes the preserved contribution-rate wording and count-sorting context. The five missing-input cases preserve their original public row keys and the retained runner excerpts. In those retained invocations, the focal TDoc/WI, the `xxx` prefix, or the own-company perspective needed for “other companies” is unbound. The company-perspective case also retains separate agenda/topic, co-submission, and cutoff questions; no focal company is invented. This does not claim that a future input-bound lookup is impossible, or that no historical fixture could ever be recovered.

The witnesses are complete emitted rows of the stated **finite diagnostic projections**: 4,160 rank paths, 18,577 trend paths, 3,942 Section-to-Spec operands, and their typed section edges. They are conditional derived data, not an independently complete transcription of all original Word/Excel/standard sources. A public-only run reproduces the bundled arithmetic; it does not independently prove extraction completeness from the archived graph. `provenance.json` pins the public source commit, immutable index, graph source hashes, and retained measurement receipts. The anonymous access check fetched only the pinned small Git files, not the archived body TTLs.

For a separate full-graph check, `reproduce_full_sqlite.py --db-dir PATH` executes the standalone queries in `sources/` against already restored immutable `RAN1.sqlite`, `RAN3.sqlite`, and `RAN4.sqlite`. Those databases are not bundled. Their reconstruction needs the separately archived body-text graphs and the released loader. This package does not claim to have freshly re-imported those public archives.

The partition is an audit of the pinned release, not a general claim that these question forms are defective or permanently unanswerable. The 494 status means the existing released answer-contract checks passed; it does not certify complete physical-source truth. The 52 evidence-pending items are not automatically classified as ambiguous. All classifications are AI research diagnostics; expert validation remains zero.
