# Core disposition audit

This diagnostic overlay accounts for all 560 original questions: **499 contract-verified, 18 requiring clarification, 8 lacking necessary source facts in the pinned frozen data, and 35 with evidence verification incomplete**. The eighteen comprise five unresolved operational metrics, five missing required inputs, one missing result extent, three conflicting TR study descriptions, one conflicting agenda description, one conflicting pack scope, and two source-availability scope conflicts. The existing current-core index remains 499 admitted and 61 nonadmitted. Reclassifying those 61 adds no solved question, model score, human review, or expert validation.

The classification uses the pinned current **question-first semantic review criteria**: derive the requested meaning from the original English and preserved source context before checking a query. This scope matters. The original queries already choose executable metrics, and the legacy query-derived contracts record their ordering and cutoffs. **If those queries are adopted as the normative task specification, the corresponding operational choice is fixed.** These diagnostics then show sensitivity to a different chosen metric, rather than multiple correct results for that fixed query. The alternative metrics here are illustrative probes, not replacement gold answers.

Run the complete portable check with Python 3 and its standard library:

```sh
python verify_package.py
```

The check loads the bundled compressed conditional graph witnesses into an in-memory SQLite database and compares their aggregates with separate Python set recounts. It also checks a conditional recent-meeting witness with calendar order and counts held fixed, then rebuilds the disjoint 560-item overlay. Meeting counts in that additional witness are retained derived observations: the portable extent check does not recount archived TDoc edges. It requires no private database, API, model credit, or network connection. To regenerate the overlay elsewhere:

```sh
python build_partition.py --candidates metric_classification_candidates.json --candidates missing_input_classification_candidates.json --candidates extent_classification_candidates.json --candidates conflicting_entity_description_candidates.json --candidates conflicting_agenda_description_candidates.json --candidates completed_scope_classification_candidates.json --output-dir audit-output
```
