This package reconstructs a separate RAN1 source snapshot by adding five positively authenticated actual Word tables and their ten original-ontology forward/inverse ownership edges. Both original ZIP archives, both exact DOCX members, extracted XML, eight caption OMML objects, all typed source metadata, the small RDF delta and node/edge mapping are preserved. Every old field, node and relationship remains intact. No full physical extraction completeness is claimed.

CQ008 retains the unchanged original English and all four required fields (TS identity and section/table/figure counts), aggregated over the original eight families and retained release-aware objects. CQ041 retains its unchanged original English and required Section identity set, using direct five-or-more-table containment. These are separate source-snapshot contracts. Existing frozen gold and the current original-Core index are unchanged. Source5 diagnostic native/SQL evidence is historical execution evidence, not new paid model performance. Two exact AI semantic judgments are included; the actual source5 full native/independent inverse SQL gate and 34 scorer controls (19 CQ008 and 15 CQ041) are included. Run `python3 evaluation/verify_controls.py --package .` to replay every requested field, both reviews, full native/SQL records, and all control outcomes. Add `--sql /path/to/fresh/RAN1.sqlite` to execute both independent queries against your isolated rebuilt snapshot. No expert or human validation is claimed. The generic prediction-scoring CLI is copied byte-exact from the prior separate-source release; its historical docstring says Source17, while all executable task/gold inputs here are exactly the two Source5 contracts.

Authenticate sources with `python3 verify_rebuild.py --package .`. Rebuild a new isolated graph with `python3 verify_rebuild.py --package . --base-sql /path/to/frozen/RAN1.sqlite --base-ttl /path/to/frozen/RAN1-body.ttl --out-dir /new/nonexistent/output`. The frozen SQLite can be recreated using the released relational materializer. The verifier never starts a server or calls a model, never overwrites an output, and preserves all 89 baseline SQL tables with full-column two-way EXCEPT checks. SQLite page bytes may differ across rebuilds; full logical old-population preservation is the claim. RDF baseline plus exact pinned delta is byte-identical to the already materialized source5 RDF.

Source field strings contain the original recorded local source identifiers as provenance. They are preserved values, not runtime dependencies; all source verification and rebuilding uses only relative package paths plus explicitly supplied baseline files.

The preserved v2 portable replay failed because historical controls were diagnostic scores while the packaged tasks are validated. The v3 verifier explicitly replays both modes: all historical controls must match exactly in diagnostic mode, and every score and validity result must also match in validated mode; only `diagnostic_only` changes. No task, answer, control, source, scorer, or kernel value was changed.

Each task also has a standalone single-task scoring folder under `evaluation/RAN1_P3_CQ008` and `evaluation/RAN1_P3_CQ041`, with byte-identical task/gold lines and scorer dependencies. The combined two-task interface remains available.
