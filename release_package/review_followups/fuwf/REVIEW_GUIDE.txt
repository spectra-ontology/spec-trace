Executable source-derived SQL and RDF/SPARQL views

all37 paired queries and expected rows, complete engine outputs, input hashes and
record counts. The producer builds a temporary in-memory SQLite database directly
from the CSV/JSON files, serializes the RDF as N-Triples, then reimports that file
before SPARQL execution. No binary operational database is packaged or accessed.
RDF predicates express literal source declarations rather than frozen Section
nodes or adoption. All112 declarations, all15 recorded discrepancy cases, all5
unresolved CR cases and all3 excluded liaison fields remain inspectable.

The37 query pairs comprise all25 observed/addressed RAN WG pairs, five declared
CR-release filters, all declared memberships, all recorded discrepancies,
three discrepancy-kind filters, unresolved CRs, and excluded liaison fields.
Expected rows are calculated directly from source-derived CSV/JSON before either
engine is built; they are not independently expert-certified native-source gold.
Both engines return the expected records on all37 checks. The discrepancy queries
retrieve the existing ledger; they do not independently discover new defects.
These checks demonstrate query/export correctness and source-locator access,
not model performance, speed superiority or measured practitioner utility.

With Python3.10+ and rdflib7.6.0 available, run from a fresh extraction:

Verification and source ownership

Run python3 -B verify_refinement.py from this directory. It checks
packaged hashes, fixed-case identities, latest counts, declared CSVs, routing
alignment, report extension, trace evidence, fresh37SQL/37SPARQL executions, and
the retained75 trial scores. Offline validation
does not reauthenticate source bytes or rerun models. Native re-audit requires
the pinned original ZIP/DOC(X)/XLSX inputs, frozen TTL, Python/openpyxl, antiword
and LibreOffice where declared; relevant producer scripts are included.
The boundary/comparator/PDF producer requires the pinned original frozen TTL,
GraphML/JSONL, WG ZIP, network access to official sources, and PyMuPDF1.27.1.
Its initial setup failures (CSV column name, absent PDF CLI, PDF hyphen wrapping)
are retained locally with the failed producers. The corrected run uses the same
fixed example and all47 existing liaison IDs; no new sample or model output was drawn.

Full original documents, converted FODT/profile data, frozen TTL, comparator
graphs, PDFs, host/process logs and private home/model-thread identifiers are
excluded. Metadata paths are anonymized where necessary; source and packaged
hashes are separate. Original field/excerpt ownership remains with the 3GPP
document providers and cited resource authors; no new ownership or relicensing
of source text is asserted. The old bundle remains unchanged as historical evidence.
