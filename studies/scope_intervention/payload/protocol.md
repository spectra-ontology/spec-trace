# SQL scope 값 개입 사전 프로토콜

이 작업은 **새 측정**이다. 저장된 SQL의 scope 표기 차이가 현재 스냅샷의 실행 정답률에 기여한 범위를, 기존 분류 전체에 대한 단일 개입으로 측정한다. 모델 응답을 새로 생성하거나 기존 질문·정답·원본 DB를 바꾸지 않는다. 이 문서는 개입 실행과 새 결과 열람 전에 작성한다.

## 고정 코호트와 개입

- 공개 패키지의 `responses/final/supplement_cycle/query_writers/miss_clusters_ten_runs.json`에서 `emptyWithoutStoredScope`로 분류된 298개 원래 `(WG, session, item)` 쌍 전부를 코호트로 삼는다. 입력 분류·응답·문항·실행 코드와 DB의 SHA256을 기록한다. 다른 실패를 합치거나 성공 항목으로 바꾸지 않는다.
- 저장된 원래 SQL에서 `scope` 열의 동등 비교 또는 `IN` 조건에 들어간 잘못된 문자열 리터럴만 실제 저장값 `whole_target`으로 치환한다. 식별자, 연산자, 조인, CTE, 투영, 정렬, LIMIT 및 다른 상수는 그대로 둔다. 수정 대상 문법이 이 규칙에 맞지 않으면 해당 항목을 명시적으로 보류하고 개입 전후 문자를 기록한다. 출력 정답을 보고 추가 수정하지 않는다.
- 실행 전 298개 원문·수정문, 문자 위치, 변경 전후 리터럴, unified diff를 가진 편집 매니페스트를 고정하고 해시한다. 실제 SQL 형태를 조사하여 필요한 문법 범위를 명시하는 보충 기록은 실행 전에만 추가한다.

## 실행과 비교

- 공개 패키지 원본 SQLite의 해시가 같은 별도 복제본을 `mode=ro&immutable=1`로 열고, 원래 Python/SQLite 런타임과 원래 평가기의 SQL 추출·첫 열 TDoc 정규화·정확 집합 비교를 사용한다. DB 수정 권한을 막고 원본 파일의 사후 해시를 확인한다.
- 원문과 수정문을 항목별로 짝지어 실행한다. 각 쿼리의 원래 60초 제한을 유지하고, 한 작업자에서 순차 실행한다. 항목별 오류·시간초과·실행시간·반환 행·정규화된 실제 집합·공개 gold 집합과 정확 일치를 보존한다. 자원 제한에 걸린 실행은 정답/오답 대신 그 상태로 남긴다.
- 먼저 존재하는 `(WG, session, family)` 층 각각에서 `SHA256(WG + session + item)`이 가장 작은 한 항목을 고르는 결정적 파일럿을 실행한다. 파일럿 결과와 실제 비용을 부모 에이전트에 보고한 뒤 같은 매니페스트로 전체 298개를 실행한다. 파일럿도 전체 집계에 포함하며 결과를 보고 코호트·치환을 바꾸지 않는다.
- 프로세스 메모리 상한은 2 GiB이며, SQLite 임시 저장은 파일을 사용하고 캐시 상한을 기록한다. 한 번의 배치는 총 60분에서 체크포인트를 남기고 멈춘다. 진행 로그를 남겨 같은 항목의 불필요한 반복을 피한다. 이 상한은 질의 시간 제한과 별개인 호스트 보호 장치다.

## 사전 정의 산출물과 해석

- 전체 및 WG/session/family별 원문·수정문 정확 일치, 오류, 시간초과, 성공 전환, 잔여 불일치를 보고한다. 잔여 항목은 실제 반환 집합의 false positive/false negative 수와 SQL의 수정되지 않은 부분으로 기술하며 원인을 추가 실행 없이 단정하지 않는다.
- 기존 297개 순서/집합 비교 확장 문항과 주 워크로드의 참조 SQL을 모두 구조적으로 기술한다. JOIN 키워드 수, SELECT 블록 수·중첩 깊이, CTE/재귀 CTE, EXISTS/NOT EXISTS, EXCEPT/INTERSECT/UNION, GROUP BY/HAVING, ORDER BY/LIMIT, 집계/윈도 함수 유무를 사전에 정한 항목으로 센다. 이는 SQL 구문의 기술 통계이며 추론 깊이·모델 능력의 척도로 해석하지 않는다.
- 핵심 추정량은 “이 고정 DB·저장 SQL에서 scope 리터럴만 바꿨을 때 정확 집합 일치가 회복된 비율”이다. 298개는 기존 실패 조건부 코호트이며 전체 모델 성공률이나 새 생성 능력의 추정으로 확대하지 않는다. 단일 DB에서의 일치는 모든 가능한 DB에서의 의미 동치와 구분한다.

## 선행 원문 대조

[Zhong, Yu, Klein, EMNLP 2020](https://aclanthology.org/2020.emnlp-main.29.pdf), §§1–3은 한 DB에서의 결과 일치와 모든 DB에서의 의미 동치를 구분하고, gold 질의의 한 요소를 바꾼 이웃 질의와 생성 DB 집합으로 평가를 강화한다. 여기서는 새 의미 동치 평가법을 주장하지 않고 실제 공개 DB에서 좁은 상수 개입의 효과만 측정한다.

[Liu et al., NL2SQL-BUGs](https://arxiv.org/html/2503.11984v1), §§2–3.2.3, 3.2.5는 저장 표현에 맞지 않는 값과 복합 조건 오류를 구분한다. scope 표기 오류 자체의 새로운 분류를 주장하지 않고, 이미 분류된 전체 코호트의 통제된 재실행으로 값 연결 문제와 수정 후 잔여 작업을 분리한다. 두 원문은 본 프로토콜 작성 전에 직접 확인했다.

## 실행 전 문법·평가기 확인 기록

첫 프로토콜 SHA256은 `c24575ae96b6d03ad1f00591b75d0e6c9c40577732e79727aa4096ec0f20e2c1`이다. 원본 코드·저장 SQL의 문법만 읽고 개입 실행 전 다음을 확정했다. 세 세션 모두 scope 열에 LOWER와 공백/밑줄/하이픈 제거를 적용한 뒤 IN 목록과 비교한다. 따라서 저장값 `whole_target`은 그 식에서 `wholetarget`이 된다. **각 scope IN 목록의 첫 `'wholedocument'` 리터럴 하나만 `'wholetarget'`으로 바꾼다.** 다른 대안 리터럴과 구문은 유지한다. 세 세션의 모든 대상에서 동일한 정확 문자열 조건을 검사하고, 한 대상에 해당 위치가 둘 이상이면 자동 중단한다.

원래 `run_chain_eval.solve_text2sql`은 첫 열만이 아니라 요청한 모든 열을 문자열화하고 최대 2,000행을 반환한다. 앞 문단의 “첫 열 TDoc 정규화”는 초기 계획의 잘못된 설명이며, 실제 실행은 **원본 solve_text2sql 함수와 score_chain_eval.score의 전체 행 집합 규칙**을 그대로 사용한다. 이 정정은 어떤 개입 결과도 실행·열람하기 전에 고정했다. 반환 전체 행 수와 2,000행 절단 여부도 기록한다. 원래 progress handler는 VM 명령 100,000개 간격으로 60초 wall clock을 검사한다.
